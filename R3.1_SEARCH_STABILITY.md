# ZERO 2.5 R3.1 — Search Stability Checkpoint

## Why this checkpoint exists

R3 introduced several speculative search changes at once. Fixed-depth A/B tests showed a clear strength regression versus the previous R2 search.

R3.1 therefore rolls back the speculative `search.cpp` changes while retaining the already-validated infrastructure work:

- corrected en-passant handling in `position.cpp`
- semantic move identity for TT/killer/counter comparisons
- TT occupancy fix
- industrialized staged `MovePicker`
- complete CMake source set
- existing perft / integrity / smoke tests

## Controlled evidence

Start position, depth 10:

- R2 baseline: `1,291,840` nodes, `e2e4`
- R3: `702,244` nodes, `d2d4`
- R3.1: uses the R2 search core with the staged MovePicker

Known tactical position after 25.Rd1 from Round 5:

- R2 baseline at depth 8: `f3d4`
- R3 at depth 8: `e1e2`
- R3.1 at depth 8: `f3d4`

All three existing regression tests pass in the R3.1 build:

- perft: PASS
- search_smoke: PASS
- position_integrity: PASS

## Engineering rule going forward

Search changes are now introduced one subsystem at a time and must pass:

1. correctness tests
2. fixed-position tactical regression
3. node-count / depth sanity check
4. self-play comparison

No bundled selective-search tuning will be accepted merely because it builds or passes perft.
