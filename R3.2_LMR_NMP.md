# ZERO 2.5 R3.2 — LMR / NMP Industrial Candidate

## Objective

R3.2 begins the selective-search tuning phase using Stockfish 19 (`sf_19`) as an architectural reference, not as a codebase to copy.

## LMR changes

- Precomputed logarithmic reduction table in 1/1024-ply units.
- Context-aware reduction from:
  - depth
  - move count
  - quiet-move history
  - PV vs non-PV node
  - cut-node status
  - TT move status
  - alpha-beta window width
  - improving flag
- LMR remains restricted to late, quiet, non-checking, non-promotion moves.
- Moves from check are never reduced.
- Reduced moves that raise alpha receive a full-depth re-search.

## NMP changes

- NMP is restricted to non-PV cut nodes.
- Dynamic reduction depends on depth and static-evaluation margin over beta.
- NMP is disabled after a null move and during verification windows.
- Null-move cutoffs do not write a fake full-depth TT entry.
- Deeper cutoffs receive a verification search before being accepted.
- Mate-like null scores are not accepted as ordinary NMP cutoffs.

## Validation

ASan + UBSan debug build:
- perft: PASS
- search_smoke: PASS
- position_integrity: PASS
- sanitizer diagnostics: none observed

A first fixed-depth comparison showed that R3.2 reduces node counts on several standard perft positions while preserving the same best move on those positions. The start position's shallow best move changed, so this branch is treated as a tuning candidate, not a proven strength upgrade.

## Engineering rule

No parameter is declared "elite" from one game or one benchmark. LMR and NMP must be validated independently across tactical regressions, node-efficiency tests, and self-play before becoming the production branch.
