# ZERO 2.5 R3.3 — SPSA-Tuned Logarithmic LMR

## Objective

R3.3 introduces the first automated search-parameter tuning loop. The existing R3.2 logarithmic LMR interaction is preserved, while SPSA is allowed to tune three coefficients:

- `LMRBase` — additive reduction offset (1/1024-ply units)
- `LMRDepthCoeff` — independent `ln(depth)` coefficient
- `LMRMoveCoeff` — independent `ln(moveCount)` coefficient

Runtime model:

`R = LMRBase + (2872/128)^2 * ln(depth) * ln(moveCount) + LMRDepthCoeff * ln(depth) + LMRMoveCoeff * ln(moveCount)`

The result is precomputed into a `[depth][moveCount]` table, so SPSA never enters ZERO's hot search path.

## Why this shape

The 503 cross-term is frozen from the R3.2 baseline for the first tuning stage. That makes the first experiment scientifically narrow: SPSA can change the reduction floor and the separate depth/move sensitivity without simultaneously changing every degree of freedom.

## Tuning architecture

`tuning/spsa_lmr.py` implements: common-random-number self-play, paired `theta+` vs `theta-` matches, deterministic opening prefixes, parameter clipping, resumable JSON state, and an optional regression gate against an anchor configuration.

The harness is deliberately independent of the C++ search implementation except for UCI options.

## Benchmark philosophy

Win/loss is not the sole objective. The harness separates:

1. self-play score against the paired SPSA candidate,
2. fixed-position regression protection against the anchor,
3. search-node efficiency as a secondary signal,
4. an unseen holdout path for later validation.

The default regression file contains the existing correctness/perft FENs as a smoke gate; these are not treated as chess-strength labels. Add forensic positions with explicit descriptions as ZERO discovers them.

## References used for design

- Stockfish 19 search architecture: official `sf_19` search implementation.
- Stockfish testing guidance: SPSA parameter ranges, perturbation clipping, common test discipline, and the recommendation to use normal time controls for search parameters.
- 2025 FIDE/Google Efficient Chess AI Challenge write-up: OpenBench/SPRT plus SPSA in a real competitive engine workflow.
- ZeroG: separate Texel/L-BFGS evaluation tuning from SPSA search tuning.
- Rusty Rival 1.0.37: SPSA-tuned LMR history/continuation parameters and repeated tuning runs.
- Black Marlin: history-based LMR adjustments and reduced PV/improving-node reductions.

## First-stage SPSA defaults

`A_k = 32 / (k + 8)^0.602`
`C_k = 24 / (k + 1)^0.101`

These are starting hyperparameters, not claims of optimality. They should be validated by the tuning logs.
